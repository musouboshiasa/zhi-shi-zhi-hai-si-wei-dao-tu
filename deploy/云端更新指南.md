# 知识之海 云端更新指南

> 当你**在本地电脑上修改了软件**（加了功能、修了 bug），需要把改动"搬"到服务器上才能生效。
> 核心就三步：**上传 → 覆盖 → 重启**。

---

## 📌 先说清楚：云端有 2 个服务

| 服务 | 在服务器上的位置 | 重启命令 | 作用 |
|---|---|---|---|
| 知识之海主应用 | `/opt/knowledge-sea/` | `systemctl restart knowledge-sea` | 网页版本体（/ruanjian） |
| 云端中转服务 | `/opt/knowledge-sea-server/` | `systemctl restart knowledge-sea-server` | 云端同步接口（/transfer） |

> 你改了什么文件，就更新哪个服务。两个都改了，两个都更新。

---

## 第 1 步：找到要更新的文件（本地电脑）

在你的本地项目文件夹里，常见的改动位置：

| 改了什么 | 要上传的文件/文件夹 |
|---|---|
| 网页界面样式 | `public/`（整个文件夹） |
| 网页功能逻辑 | `public/` |
| 后端程序 | `server.js` |
| 部署配置 | `deploy/` |

## 第 2 步：WinSCP 上传覆盖

1. 打开 WinSCP 连接服务器
2. 左边（电脑）进入本地项目文件夹
3. 右边（服务器）进入对应服务目录
   - 改主应用 → `/opt/knowledge-sea/`
   - 改中转服务 → `/opt/knowledge-sea-server/`
4. 把改过的文件**拖到右边同名位置覆盖**
   - 弹窗问"是否覆盖？" → 点 **是**
   - 如果只改了一两个文件，可以只拖那一个文件

## 第 3 步：重启服务（SSH 终端）

覆盖上传后，**必须重启**才能生效：

```bash
# 更新了主应用就执行：
systemctl restart knowledge-sea

# 更新了中转服务就执行：
systemctl restart knowledge-sea-server
```

重启后验证：
```bash
systemctl status knowledge-sea          # 看到 active (running) 即成功
```

---

## 🔄 更新流程总览（以后照着做）

```
本地改代码
   ↓
WinSCP 拖文件覆盖到服务器
   ↓
SSH 执行 systemctl restart 对应服务
   ↓
刷新浏览器验证
```

## ⚠️ 常见问题

### Q: 上传了但界面没变化
- 没重启服务 → 执行 `systemctl restart knowledge-sea`
- 浏览器缓存 → 按 `Ctrl + F5`（强制刷新）

### Q: 重启后网页打不开
- 查看日志找原因：
  ```bash
  journalctl -u knowledge-sea -n 30
  ```
- 常见原因：上传时少传了文件、`server.js` 语法错误

### Q: 改了中转服务（云端同步）不生效
- 确认文件传到的是 `/opt/knowledge-sea-server/` 而不是主应用目录
- 确认重启的是 `knowledge-sea-server`（注意名字带 server）

### Q: 更新了前端但样式还是旧的
- 把 `public/` **整个文件夹**重新传一遍（不是只传一个文件，防止漏文件）
- 强制刷新浏览器

## 📝 小建议

- **改代码前**，先备份服务器上的原文件（WinSCP 右键 → 复制到本地）
- 每次更新后，顺手在浏览器验证三个入口：
  - `https://musouboshiasa.com/ruanjian/`（主应用）
  - `https://musouboshiasa.com/`（云端首页）
  - `https://musouboshiasa.com/drive`（网盘）
